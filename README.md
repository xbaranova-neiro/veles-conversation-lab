# Велес · Лаборатория диалогов

Локальный браузерный прототип тёплого первого контакта и сбора лида. Не подключён к Авито и Битрикс24, не отправляет сообщения клиентам. После получения номера создаётся только локальная тестовая карточка.

## Запуск

Нужен Node.js 22 или новее. Внешние зависимости не требуются.

```bash
cd '/Users/karinakomak/Documents/Codex/2026-09-15/new-chat/outputs/veles-prototype'
npm start
```

Открыть [прототип](http://127.0.0.1:4173/). Используйте именно 127.0.0.1, а не localhost. Сервер доступен только на этом компьютере. Если порт занят, можно задать `VELES_PORT` при запуске.

## Как тестировать

1. Пишите в чат своими словами или выбирайте один из шести сценариев. В сценарии каждую реплику отправляете самостоятельно; между ними можно дописать свою.
2. Справа видно, что записалось в карточку клиента. Во вкладке «Ход диалога» — причины передачи и ограничения на контакты.
3. После передачи новые сообщения дополняют карточку; помощник замолкает. «Не беспокойте» отменяет тестовую передачу и прекращает ответы.
4. «Новый диалог» очищает текущую проверку. Сначала можно скачать JSON с перепиской, фактами и событиями.
5. «Проверка качества» повторяет локальные проверки сценарного движка.

## Два режима

**Сценарный** — работает сразу и бесплатно. Это распознавание фраз и память диалога, не языковая модель. Он ограничен и может не понять необычную формулировку. Подходит для проверки последовательности вопросов, карточки и передачи.

**AI** — для локального теста можно в «Настройках AI» выбрать живую модель и ввести ключ. Для общей ссылки ключ задаётся только на сервере переменной `OPENAI_API_KEY`; в браузер он не попадает. Название модели задаётся через `OPENAI_MODEL`. В примере заполнено `gpt-6-astra`; доступность зависит от API-аккаунта. Запросы оплачиваются отдельно по API-тарифу.

Ключ привязан к сессии и хранится только в памяти сервера; не записывается в файл и не возвращается браузеру после сохранения. Ключ можно удалить в настройках. Текст тестового диалога и ограниченная база передаются в OpenAI; используйте вымышленные контакты. Не вставляйте ключ в переписку с разработчиком.

Подключение реализовано через [Responses API](https://developers.openai.com/api/reference/typescript/resources/responses/methods/create), JSON Schema и `store:false`. Наличие `store:false` не означает обещание отсутствия любой обработки/хранения со стороны провайдера.

AI определяет смысл сообщения и предлагает короткий ответ. Локальная логика управляет фактическим состоянием: контакт, запрет звонков, остановка, передача. Она ограничивает длину, количество вопросов, неподтверждённые числа, служебные фразы и ложные сообщения о выполненных действиях. Это дополнительные проверки, а не абсолютная гарантия отсутствия ошибок модели.

## Что обновлено по замечаниям владельца

- Убраны ссылки на сайт как обоснование клиентских ответов и фразы о расхождении/неподтверждённости данных.
- В диалоге собираются планы клиента: площадь, назначение дома, район и участок, сроки, бюджет, способ оплаты и пожелания. После нескольких содержательных деталей помощник естественно предлагает созвон.
- Учтено предоставленное объявление: три области, гарантия 5 лет на газобетонный дом, участок оплачивается отдельно.
- Внутренние источники и ограничения видны только в служебной панели и базе.

## Проверки

```bash
npm test
```

Проверяются диалоги, сохранение/исправление данных, отказ от контактов, исключение дублей, HTTP-сессии, CSRF, ошибки и адаптер AI с подставными ответами. Тесты не обращаются к OpenAI и не расходуют деньги. Живые AI-диалоги без предоставленного ключа не проверены.

Сессии хранятся в памяти сервера до перезапуска или истечения 8 часов бездействия. Обновление страницы на работающем сервере сохраняет переписку. Перезапуск сервера очищает диалоги и ключи. Максимум 100 сообщений на диалог и 2000 символов на одно сообщение.

Содержимое: `engine.mjs` — логика; `ai.mjs` — AI и инструкции; `server.mjs` — локальный сервер; `public/` — интерфейс и база; `checks.mjs` и `tests/` — проверки.

## GitHub и общая ссылка

Репозиторий можно хранить на GitHub. Обычного GitHub Pages недостаточно для AI-режима: Pages не запускает сервер и не умеет безопасно хранить API-ключ. Для публичного теста подключите репозиторий к Node/Docker-хостингу и задайте там секрет `OPENAI_API_KEY`.

В проекте есть `Dockerfile` и `render.yaml`. На Render достаточно создать Blueprint из репозитория и добавить секретный ключ в настройках сервиса. После публикации Алексей получит одну обычную HTTPS-ссылку; интерфейс и сервер будут работать вместе.
